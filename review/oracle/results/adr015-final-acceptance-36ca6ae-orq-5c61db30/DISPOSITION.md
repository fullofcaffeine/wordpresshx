## Integrated conclusion

Retain Oracle's `do not accept` verdict. Current `main` contains one directly
reproduced critical authority-forgery seam and five major defect groups. Bead
`wordpresshx-g6.1` must remain `in_progress`; ADR-015 must remain `proposed`;
the receipt must continue to withhold acceptance and publication authority.

No product implementation was made in this reconciliation. Two required
corrections depend on consequential owner choices: the artifact identity that
tokens promise and the non-caller-controlled trust anchor for the expected
content root. Partial parser, test-adapter, validator, or evidence edits would
not make this review acceptable and would create another non-final review
subject. The next remediation should make those choices explicit, implement
the six retained repair groups as one evidence-coherent revision, then obtain
a new exact-revision Oracle review.

Minimum safe next revision:

1. Remove the product-visible `FixtureTargetAdapter` and add direct
   product-classpath negatives on interpreter, PHP, and JavaScript.
2. Parse a closed JavaScript formal grammar and add an independent source-shape
   negative that does not import `abi_model.py` or generator functions.
3. Add a non-forgeable product-owned complete-bundle verification handle whose
   expected root is not supplied by the candidate bundle or caller.
4. Make token artifact identities denote exactly the bytes each target
   observes, or verify the full distribution before minting authority.
5. Validate every safety-bearing capability and authority field through the
   exact `ArtifactOwner` StageValidator before any transaction effect.
6. Bind authoritative inputs, physical generated members, observer code,
   dependency locks, workflow, and gate into one non-recursive evidence subject
   digest with separate durable observer outcomes.

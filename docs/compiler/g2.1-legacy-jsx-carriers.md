# G2.1: legacy JSX carrier decision

WordPressHx currently retains three generated `any[]` locals in the SDK-032
fixture. They are private compiler scaffolding, not application data or public
API:

- `Main.App:tmp:any[]`
- `Main.ProofCheckRow:tmp:any[]`
- `Main.ProofCheckRow:tmp1:any[]`

The live SDK-032 gate inventories those three declarations from the generated
TypeScript AST. It also proves that no `any` or `unknown` reaches a public
field, parameter, return type, prop, event, ref, hook, or context boundary. A
new weak local, a missing expected local, or a public weak type fails the gate.

## Why the locals exist

Genes 1.36.3 models a JSX marker as a tag plus heterogeneous property and child
arrays. “Heterogeneous” means one array can contain records whose values have
different types—for example, a string CSS class, a Boolean ARIA state, and an
event callback. The compiler-facing extern therefore owns an
`Array<Dynamic>` boundary.

Haxe sometimes lifts one of those arrays into a temporary before nested JSX is
evaluated. Genes then reads fixed paths such as `tmp[0].value` instead of
printing the initializer again. That preserves two JavaScript guarantees:

1. each prop or child expression runs exactly once; and
2. parent props, nested children, and later siblings run in source order.

Removing the `any[]` annotation alone is not a type-safe fix. TypeScript would
infer a mutable array of unions, not a fixed tuple whose index identifies one
exact value type. Inlining the initializer is also unsafe when it repeats or
reorders an expression with a call, getter, proxy read, mutation, or exception.

## The generalized upstream solution

Genes PR [#10](https://github.com/fullofcaffeine/genes-ts/pull/10) replaced the
weak marker arrays with generic linked property and child records. Each link
retains its own Haxe type, so the compiler can preserve order without storing
unrelated values in one weak array. The PR is framework-neutral: its compiler
code and fixtures contain no WordPress identity. Its complete upstream CI
passed across strict TSX, erased JSX, typed `createElement`, classic JavaScript,
multiple TypeScript versions, the todo app, security checks, and ts2hx.

That work was released in Genes 1.37.0 and is also present in the exact 1.37.1
release. A local run of the current upstream TSX gate passed. Conversely,
compiling the current WordPressHx adapter against current Genes fails closed:
the adapter still emits the old heterogeneous arrays, while the new protocol
requires typed linked records.

This means the safe next step is a coherent compiler-line migration, not a
WordPress-specific Genes patch and not a one-line annotation edit. Bead
`wordpresshx-g2.5` owns that migration: update the HXX adapter, admit an exact
Genes release, refresh all compiler-dependent receipts, and prove strict and
classic evaluation equivalence. Until then, the three generated-only locals
remain a precise, fail-closed legacy inventory.

“Provenance” in this decision means the reviewable chain showing where the
compiler behavior came from: upstream PR, commits, CI, release tag, release
artifact digest, and the exact downstream pin. The machine-readable chain is
recorded in
